# An opinion's text is one named field, chosen for fidelity

Status: accepted

A court opinion is stored as one node with one blob of text
(`docs/adr/0006-a-document-node-is-class-neutral.md`, #53). A CourtListener
opinion record carries the text in up to **eight** fields, populated by different
donors at different quality, and the record says nothing about which one to take.
So something has to choose, and the choice is expensive to revisit: it decides the
characters in the file, the provenance recorded beside them, and — because the
U.S.C. extractor runs over the stored text — which citations the dataset holds at
all.

The fields, with the publisher's own words for where each comes from:

| Field | Populated when |
|---|---|
| `plain_text` | "we got the opinion from a court's website as a PDF or Microsoft Word document" |
| `html` | from a court's website as WordPerfect or HTML, or from Resource.org |
| `html_lawbox` | "the Lawbox donation" |
| `html_columbia` | "the Columbia collaboration" |
| `html_anon_2020` | "our anonymous source in 2020" |
| `xml_harvard` | "the source was Harvard's Caselaw Access Project… not always perfect due to being created by OCR" |
| `xml_scan` | the scanning project; undocumented on the API help page |
| `html_with_citations` | the text with CourtListener's own citation markup added |

`docs/research/courtlistener-formats.md` section 1 records four different
preference orders inside CourtListener's own codebase, and recommends a fifth:

```
xml_harvard > html_anon_2020 > html_columbia > html_lawbox > html > plain_text
```

## The decision

**Take the text from the first field present in this order, and name that field in
the node's provenance.**

```
plain_text > html_anon_2020 > html_columbia > html_lawbox > html > xml_harvard
```

`xml_scan` and `html_with_citations` are not read at all.

**That is the published order reversed at both ends, and it is not a mistake.**
The published order ranks the fields for a reader that wants *structure*: typed
opinions, named authors, footnotes, star pagination. It is right for that. This
crate parses no structure — an opinion is one node and gaining children is later
work — so the only question left is whether the characters are the ones the court
printed. On that question the ranking inverts:

- `plain_text` is `pdftotext` over a document the publisher supplied. No structure
  at all, and the characters are the publisher's own. Best.
- the donated HTML archives were prepared by editors; a person handled the text.
- `html` is a court's markup or Resource.org's; quality varies widely.
- `xml_harvard` has the best *coverage* of any field, two thirds of the corpus,
  and the worst text. CAP states it plainly: "Case text and general head matter
  has been generated by machine OCR and has not received human review." Last.

`html_with_citations` is excluded because it is a derivation rather than a record
(`docs/adr/0007-a-record-is-what-was-said-everything-else-is-derived.md`): it is
one of the six fields above with CourtListener's own annotations added, and for a
PDF-sourced opinion it is `plain_text` wrapped in `<pre>`. Storing it would store
a second party's derivation as though it were the document.

### The field decides what may be claimed, and `extracted_by_ocr` overrides it

Each field carries a default `Provenance.method` and `VerificationState`:

| Field | Method | Verification |
|---|---|---|
| `plain_text` | `text_layer` | `Asserted` |
| the four HTML fields | `markup` | `Asserted` |
| `xml_harvard` | `ocr` | `MachineSuggested` |

`xml_harvard` is `MachineSuggested` because CAP says no person has confirmed the
words. Everything else is `Asserted`: a source is asserting its own characters.

**A record whose `extracted_by_ocr` is true is downgraded to `ocr` and
`MachineSuggested` whatever field the text came from.** The publisher has told us
a machine read the document; taking the field's own word over that would be
claiming more than we were told. Note that CourtListener sets this flag on *every*
opinion imported from Harvard, so for much of the corpus it is a statement about
the import route rather than a measurement of one document — which is an argument
for treating it as a floor, not a reason to ignore it.

### The provenance names the record and the field

`courtlistener:opinion/2651100:plain_text`, not `courtlistener`. A reader who
doubts a passage can go to the same field of the same record and read what we
read. Naming only the publisher would make the statement unfalsifiable, which
`docs/adr/0005-evidence-is-stored-once-and-never-deleted.md` exists to prevent.

### Markup is stripped, and every character reference that cannot be decoded is reported

This is the rule the whole decision turns on, because getting it wrong is silent.

CourtListener's `html` for *Encyclopaedia Britannica v. Commissioner*, a leading
26 U.S.C. § 174 case, writes every section sign as the character reference
`&#167;`. The literal character appears nowhere in the field. The U.S.C. extractor
refuses to read a section number with no marker before it, on purpose
(`crate::citation::usc`). So a tag-strip that leaves references alone yields a
text with no citation in it, and the dataset then states — confidently, with
nothing anywhere reporting a problem — that the case does not cite § 174.

*Snow v. Commissioner*, in the same corpus, writes the character itself in the
field its text is taken from. Two donors, two conventions, no warning.

So `courtlistener::markup::text_of_markup` decodes numeric references generally
and a short list of named ones, and **reports every named reference it did not
decode, with a count**, on the same contract `usc::find_with_report` has. The list
is short on purpose: HTML names over two thousand entities, a court opinion uses a
dozen, and a guess at the rest would be a character in the file that is not the
character the court printed. A hole that is named is an exclusion; a hole that is
silent is how a citation disappears.

## Consequences

No schema version moves. This decides the contents of a node's text and
provenance, both of which are already core fields of shape 9.

**The corpus is not reproducible across a change to this order.** Re-running
`add-opinions` after reordering `TEXT_FIELDS` replaces the text of stored opinions
and can change which citation links exist. The field is named in the provenance so
that the change is at least visible in the file rather than only in the diff of
this repository.

**Structure arrives later, and this order will need revisiting then.** When an
opinion gains children, `xml_harvard` becomes the only field with anything to
parse for two thirds of the corpus, and the trade-off changes from "best
characters" to "characters good enough, structure present". That is a different
decision and it belongs to whoever writes the parser.

**CourtListener is replacing these fields.** A new `OpinionContent` model with
`content`, `source` and `extraction_type` columns "replaces the previous wide
table design that had separate fields for each content source"
(`docs/research/courtlistener-formats.md`, section 4). When it lands,
`extraction_type` — "opening the document", "via OCR", "via LLM" — says directly
what this ADR infers from which field was populated, and `TEXT_FIELDS` becomes a
mapping from their vocabulary to `text_method` rather than a ranking.

## Considered and rejected

**Follow the published preference order.** Consistent with Free Law Project's own
code, and it would take Harvard's raw OCR over a court's own PDF for every record
that has both — which is most Supreme Court cases. It ranks for structure we do
not keep.

**Take `html_with_citations`, which the API help page calls "the most reliable
field for most purposes".** It is the best field for citation *offsets* and a poor
one for text: it is another field with markup added, so storing it stores a
derivation as the document, and it does not resolve statute citations anyway — a
U.S.C. citation survives in it only as `<span class="citation no-link">` with no
identifier (`docs/research/courtlistener-formats.md`, section 8).

**Concatenate every field present.** Loses nothing and produces a document that
says everything twice, with no honest single answer to "how was this text
obtained".

**Store each field as its own node, or as its own expression.** Defensible, and it
makes an opinion several works or a tree with a level the source does not have.
Two renderings of one writing are not two dates and not two parts, so neither
existing axis fits, and inventing a third to hold a publisher's storage history is
a large change to the core in exchange for data nobody has asked for.

**Decide trust from `extracted_by_ocr` alone and ignore which field was read.** It
is set on every Harvard import, so it would mark a Lawbox-donated text as OCR
whenever the record had also been merged with a Harvard one, and it says nothing
at all about the difference between an editor-prepared archive and a court's PDF.

**Decode every HTML entity.** Correct and a large table to carry and keep. The
short list plus a report gives the same safety, because a reference outside the
list is named rather than dropped, and the report is how the list grows when a
real document needs it.
